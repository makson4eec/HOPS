# Локальное хранилище

`HOPS_DATA_DIR` — приватный каталог вне public/.next. Системная запись `state.json` содержит проверенный JSON в конверте `payload + SHA-256 checksum`: пользователи, хеши scrypt, хеши токенов сессий/корзин, настройки, каталог, принятые бонусы, заказы/позиции, отзывы, подписки, ограничения частоты, аудит. `state.backup.json` — зеркало последней фиксации. Человеко-читаемые текущие выгрузки: `accepted/catalog.json`, `accepted/loyalty.json`; старые выгрузки — `archive`. Оригиналы 1С лежат в `incoming`.

Записи сериализованы межпроцессной файловой блокировкой. Изменение проходит в памяти; ошибки откатывают весь набор. Каждый файл пишется во временный файл, сбрасывается на диск и атомарно переименовывается с повтором при кратком захвате антивирусом. `pending.json` — предварительно сброшенное намерение транзакции: при следующем доступе воспроизводится полностью до ответа читателю, включая отдельные файлы заказов/исходящую папку. Для блокировок используется proper-lockfile: атомарный mkdir, heartbeat раз в 10 секунд и восстановление после 60 секунд без heartbeat. Живой владелец регулярно продлевает блокировку; потеря блокировки аварийно завершает процесс для безопасного восстановления журнала. При невозможности получить блокировку запрос завершается ошибкой.

Перед сохранением проверяются типы, диапазоны, ID, уникальность и ссылки. Битый основной файл восстанавливается из зеркала. При повреждении обоих или журнала сервер не создаёт пустое хранилище вместо существующего: требуется проверенная копия. Контрольная сумма выявляет повреждение, не заменяет ACL. При зависшем процессе сначала остановить его; не удалять блокировку у работающего HOPS.

Дневные резервные копии проверяются после записи; предусмотрена копия на другой локальный диск и восстановление. Сохранять копии отдельно от исходного диска. Архивы выгрузок и аудит автоматически не удаляются: их период хранения согласовать с магазином; контролировать свободное место. Истёкшие сессии, корзины и ограничения частоты очищаются при транзакциях.

Пароли сохраняются только как scrypt с индивидуальной солью, cookies — HttpOnly/SameSite и Secure при HTTPS. Серверные действия проверяют Origin, сессию/роль и поля. Бонусы выбираются по подтверждённой привязке текущего пользователя; страница не возвращает общий снимок. Допуск к исходящим заказам имеет только сервис/назначенная запись 1С.

Для переноса прежних данных сначала получить контролируемый экспорт прежней системы, проверить ID и совместимость scrypt-хешей. Автоматическое чтение прежней СУБД отсутствует; исходная база не изменяется этим рефакторингом.
