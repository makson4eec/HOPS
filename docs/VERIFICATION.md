# Фактические проверки

Дата: 4 сентября 2026. Среда: Windows, Node.js 24.19.0, Next.js 16.3.4, Prisma 6.19.2. Для проверки поднят временный PostgreSQL 18.4 на 127.0.0.1:55432; Docker и CI настроены на PostgreSQL 16. Тестовые записи создаются только в `hops_test` и удаляются после сценариев. В production seed товаров нет.

## Результаты по этапам

1. **Исходник:** проверен синтаксис `app.js` и `server.mjs`, просмотрены публичные и административные сценарии, стили и все HTML-оболочки. Аудит — `docs/AUDIT.md`.
2. **База и сервер:** `prisma validate`, генерация клиента, применение миграций и повторяемость seed проверены на PostgreSQL. Цены хранятся в копейках; ограничения SQL запрещают отрицательные остатки и превышение резервов. Все временные метки имеют `TIMESTAMPTZ(3)`.
3. **Приложение:** `npm run lint` и `npm run typecheck` проходят. `npm run build` проходит без `DATABASE_URL` и работающей базы во время сборки. Все страницы с бизнес-данными и sitemap вычисляются сервером при запросе.
4. **Заказы, авторизация и обмен:** `npm test` с заданным `TEST_DATABASE_URL` — **23 passed, 0 failed, 0 skipped**. Проверены параллельный заказ последней единицы, идемпотентность оформления, цена из БД, чужой ключ заказа, освобождение резервов и списание при выдаче; пароли, перенаправления, время самовывоза; пустой обмен, повторы, просроченные lease, конкурентные worker, устаревшие данные, откат страницы импорта, неизменные повторные запросы, привязка клиента и бонусные операции.
5. **Браузер:** пройдены все **29 сценариев** по отдельным прогонам: 28 проверок страниц/мобильной версии/доступности/авторизации и сквозной сценарий публикации товара, корзины, самовывоза, модерации отзыва, выдачи заказа и ручного обмена. После исправления серверного перенаправления отдельно повторены успешные проверки оформления, входа, выхода и сохранения полей при ошибке. Финальный сквозной сценарий прошёл на собранном standalone-сервере. После проверки в базе 0 товаров, 0 заказов и 0 отзывов.

Браузерный тест выявил потерю клиентского перехода после очистки корзины: повторная отрисовка удаляла форму до выполнения эффекта. Исправлено серверным перенаправлением после успешного действия, вне блока перехвата ошибок. Финальные lint и production build проходят.

Во время проверок найдены и исправлены обращение sitemap к базе при сборке, обработка PostgreSQL serialization failures и зависимость времени повторов от часового пояса базы. Сообщения об ожидаемых нарушениях SQL-ограничений в тестовом логе не являются падениями: тесты проверяют отказ в таких операциях.

## Мобильная версия, доступность и скорость

Проверены размеры 320, 375, 768 и 1440 px, отсутствие горизонтального переполнения, раскрытие меню с клавиатуры и Escape, видимый фокус, подписи полей и состояния форм. Визуально просмотрены главная, ассортимент и кабинет на мобильном экране и главная на десктопе. Axe проверяет WCAG 2 A/AA и 2.1 A/AA на главной, каталоге, кабинете, отзывах и контактах; серьёзных и критических нарушений не обнаружено. Это автоматическая проверка выбранных сценариев, а не полная сертификация доступности.

Изображение обложки преобразовано из PNG 2 174 648 байт в WebP 179 306 байт с сохранением исходного изображения. В локальном Chrome: загрузка главной около 357–365 КБ и 23–31 запрос; десктопный TTFB 34 мс, load 209 мс. Мобильные измерения при параллельных тестах: TTFB около 858–882 мс, load около 1 с. Это локальные измерения без эмуляции мобильной сети, не обещание показателей на VPS. Нагрузочное испытание и реальные Core Web Vitals после публикации не выполнялись.

## Границы проверки

- Docker отсутствует в этой локальной среде. Dockerfile и Compose подготовлены и проверены структурно; фактическую сборку образов и запуск контейнеров здесь выполнить нельзя. Workflow GitHub Actions содержит отдельный запуск Compose с проверкой БД, миграций, worker, health, непривилегированного пользователя и пустого каталога. Workflow ещё не запускался в GitHub: у исходного каталога нет git-метаданных/remote.
- `npm audit --omit=dev` дважды завершился сетевым тайм-аутом endpoint npm. Результата проверки базы опубликованных уязвимостей нет; это не утверждение об их отсутствии.
- API 1С не предоставлен. Проверены интерфейс, очередь, обработка тестовых ответов и отказ неподключённого live-режима. Реальная авторизация 1С, формат обмена и согласование остатков проверяются после получения контракта.
- HTTPS, домен, реальные контакты, документы владельца и резервное копирование на VPS требуют конфигурации по `docs/DEPLOYMENT.md`. Верификация email и восстановление пароля через почту/SMS не подключены; смена известного пароля и завершение остальных сессий реализованы.

## Сохранение исходной версии

Автоматическая проверка отклонила удаление исходных `dist` и `server.mjs`. Вместо удаления создана резервная копия `backups/hops-original-demo.zip`. Исходные файлы оставлены для сохранения уже работавшего локального демосервера и исключены из Git/Docker. Новое приложение использует только `app`, `components`, `lib` и `public`: в них нет browser storage или демонстрационных учётных данных. Резервные копии не входят в поставку.
