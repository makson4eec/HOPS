# Аудит и этапы перехода

Исходник: HTML-оболочки в dist, единый app.js, styles.css с двумя слоями визуальной системы, PNG обложки, favicon, статический server.mjs и Windows launcher. Исходных Next.js/TypeScript файлов, базы, тестов, Docker и git-метаданных нет.

Сценарии: категории и поиск, пустой каталог, корзина, самовывоз, демонстрационный вход по коду, кабинет, бонусный экран, отзывы с модерацией, CRUD товаров и настройки в админке. Карточка товара и заказы не имели отдельных страниц. Бизнес-контент и авторизация хранились в браузере. Клиент мог менять цены, статусы, права и чужие заказы. HTML зависел от JavaScript. Товары в поставке отсутствуют.

Сохраняем существующие маршруты, идентификаторы категорий, контакты (проверить владельцу перед публикацией), изображение, светлую серо-белую палитру с оранжевым акцентом. Не переносим небезопасный браузерный механизм. Товары, клиенты и отзывы не генерируются.

Этапы: 1. Аудит и проверка исходного синтаксиса. 2. PostgreSQL, Prisma, авторизация, транзакции заказов. 3. Серверные страницы и админка. 4. Обмен 1С, очередь, повтор ошибок. 5. Docker, CI, VPS и итоговые проверки.

В локальной среде первоначально отсутствуют Docker и PostgreSQL. Статус фактически выполненных проверок фиксируется в docs/VERIFICATION.md.
