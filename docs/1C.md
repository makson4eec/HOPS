# Контракт локальных выгрузок 1С

1С и HOPS работают на одном Windows-ПК. HTTP API и прямого доступа к хранилищу пользователей нет. Кодировка UTF-8, числа JSON, ISO 8601 с часовым поясом. Публиковать временный файл в той же папке и после закрытия атомарно переименовывать в конечное имя. Никогда не писать конечный файл по частям.

Пути по умолчанию: `C:\HOPS\data\incoming\catalog.json` и `loyalty.json`. Они настраиваются в `.env` через `HOPS_CATALOG_FILE`, `HOPS_LOYALTY_FILE`. Сайт проверяет файлы при запуске и затем раз в 30 минут. Если файл совпадает с предыдущим по метаданным, сайт пропускает чтение JSON. Кнопка «Проверить файлы сейчас» в админке запускает проверку сразу. Расписание создания файлов задаётся отдельно в 1С.

## Подключение обработки на ПК магазина

Комплект для файловой «Розницы (базовой)» 2.3.26.24 на платформе 8.3.27.2130 состоит из [HopsExport.epf](../integrations/1c/HopsExport.epf), [hops-1c.json](../integrations/1c/hops-1c.json) и [исходника модуля](../integrations/1c/HopsExport.bsl). Обработка читает данные учёта и записывает JSON в папку обмена. Контейнер `.epf` проверен распаковкой и сравнением модуля с исходником. Запуск на платформе и запросы к данным следует проверить на копии базы магазина.

1. Создайте резервную копию базы в 1С и откройте отдельную копию для пробы до подключения рабочего сайта к обмену. Скопируйте `hops-1c.json` в `C:\HOPS\data\incoming`. Для пробы используйте изолированную папку данных сайта. Если эта папка обмена уже обслуживает рабочий сайт, проведите пробу на другом ПК. Учётной записи 1С нужен доступ на чтение и запись папки обмена. [Настройка прав Windows](WINDOWS.md#первая-установка)
2. В режиме «1С:Предприятие» откройте «Администрирование → Печатные формы, отчеты и обработки». Включите «Дополнительные отчеты и обработки», откройте одноимённый список и добавьте `HopsExport.epf` из файла. Разместите команды обработки в доступном вам разделе. Для этой обработки требуется режим, в котором 1С разрешает читать и писать локальные файлы в `C:\HOPS\data\incoming`. Модуль запрашивает запуск вне безопасного режима. [Внешние обработки 1С](https://1c-dn.com/1c_enterprise/external_data_processors/)
3. Выполните «HOPS - проверить настройки». Откройте `C:\HOPS\data\incoming\hops-1c-diagnostics.json`. Поле `siteAllowlist` содержит готовую строку `ONE_C_ALLOWED_CATEGORY_IDS=…`. Перенесите её в `.env` сайта. Если вместо неё есть `catalogError`, исправьте настройку по тексту ошибки. В диагностике также есть список папок номенклатуры с UUID и признак внешнего дисконтного сервера. Для совпадающих имён добавьте `id` нужной папки рядом с `name` в `hops-1c.json`.
4. Задайте пути файлов в `.env` и перезапустите HOPS.

   ```dotenv
   HOPS_CATALOG_FILE=C:\HOPS\data\incoming\catalog1.json
   HOPS_LOYALTY_FILE=C:\HOPS\data\incoming\bonuska.json
   ```

5. Запустите «HOPS - выгрузить каталог» и «HOPS - выгрузить бонусы». В админке сайта откройте «Обмен 1С» и нажмите «Проверить файлы сейчас». Сверьте текущую розничную цену и свободный остаток фасованного товара, цену за единицу и дробный остаток разливного товара, затем баланс одной проверенной карты. Перед использованием на рабочей базе убедитесь, что проверка показывает новые ID обеих выгрузок.
6. В карточке внешней обработки откройте расписание обеих команд выгрузки и поставьте повтор каждые 30 минут. Проверьте появление двух последовательных свежих снимков во время работы 1С. Для файловой базы нужен работающий сеанс 1С с регламентными заданиями. При закрытой 1С сайт показывает последний принятый снимок и продолжает проверку файлов каждые 30 минут. [Регламентные задания в файловой базе](https://1c-dn.com/library/tutorials/practical_developer_guide_running_scheduled_jobs/)

### Настройки магазина

- Магазин «Пивотека ХОПС», склад продажи «Хопс», вид цен «Розница». Обработка проверяет склад по карточке магазина и берёт последнюю цену этого вида. Пустое поле валюты в регистре трактуется как рубли для этого магазина. Явно указанную валюту сверяет со списком `rubles`.
- Начальный список папок включает «Пиво Фасованное» и «Пиво разливное». Папка берётся из иерархии «Входит в группу». Для товаров в этих папках названия с «сидр»/`cider`, «пуарэ»/`poiré`, «пив. нап.»/«пивной напиток» помогают отнести смешанный ассортимент к соответствующим разделам. Сверьте результат для пограничных позиций. Добавьте остальные утверждённые папки и категории из диагностики, повторите проверку и обновите allowlist сайта. Подтверждённых папок газировок и снеков в исходных снимках экрана нет.
- Свободный остаток вычисляется по складу «Хопс» с вычетом резервов 1С. Отрицательный результат записывается как ноль, дробный остаток сохраняется. При характеристиках с собственными остатками выгрузка останавливается с кодом товара. Для таких товаров нужны отдельные правила сопоставления вариантов. Перед подключением сверьте единицы и цены, если касса использует цены за упаковку.
- Бонусная программа «Бонус 2023», вид карты «Обычная карта (бонусная)». По фото 1 балл равен 1 ₽, бонусами можно оплатить до 10% покупки в пределах сегмента «весь товар с 10/24». Для публикации правил ещё нужны условия начисления, срок действия, применимость к конкретным товарам и порядок возвратов. Обработка выгружает текущий баланс по основной карте владельца. При неоднозначной основной карте или внешнем дисконтном сервере выгрузка останавливается с ошибкой. История из отчёта «Начисления и списания бонусных баллов» требует подтверждённого сопоставления операций и пока не выгружается этой обработкой.

Модуль закрывает временный файл перед переименованием и сохраняет предыдущий файл с суффиксом `.previous`. При замене может быть короткий промежуток между переименованиями. Если HOPS проверит папку в этот момент, витрина продолжит показывать последний принятый снимок.

## Каталог

Схема: [catalog.schema.json](../schemas/catalog.schema.json), пример **только для разработки**: [catalog.json](../examples/catalog.json). Метаданные: `schema_version: "1.0"`, уникальный `export_id`, монотонный `generated_at`, `complete: true`, полный `products`. Новая выгрузка должна иметь более позднюю дату и новый ID. Повтор идентичного снимка допустим; повтор ID с другим содержимым отклоняется. Снимки с датой более чем на 5 минут в будущем отклоняются. Синхронизировать часы ПК.

Обязательные поля продукта: `externalId`, `categoryId`, `siteCategory`, `sku`, `name`, `price` в рублях (до 2 знаков), `stock`, `isNew`, `isActive`, `updatedAt`. Остальные поля описаны схемой: `barcode`, `description`, `country`, `manufacturer`, `volume`, `unit`, `alcohol`, `beerColor`, `beerFiltration`, `shelfLifeDays`, `expiryDate`, `batches`, `imageUrl`, `attributes`.

Коды сайта: `beer`, `ciders`, `poire`, `beer_drinks`, `lemonade`, `snacks`, `vapes`. `new` — только фильтр `isNew`. `categoryId` — реальный ID группы 1С, он не обязан совпадать с кодом сайта. Сайт преобразует `beer_drink` из исходного `catalog1.json` в `beer_drinks`. Цвет: `light/dark`; фильтрация: `filtered/unfiltered`. В `attributes` передавать разновидность сидра/пуарэ, сладость, вкус, упаковку, состав и характеристики других категорий; названия ключей отображаются в карточке. Поддержаны также поля `ciderType`, `poireType`, `sweetness`, `flavor`, `nicotine`, `puffs`, `composition`, `packaging` из шаблонов.

Цена внутри HOPS переводится в целые копейки. `stock` может быть дробным, но оформление поддержано только для целого количества упаковок с `unit: pcs/шт/шт.`. Изображения: `/images/имя.webp` из public либо HTTPS без логина/пароля в URL. Остальные JSON приватны.

Фильтр допуска: `ONE_C_ALLOWED_CATEGORY_IDS` **ИЛИ** `ONE_C_ALLOWED_PRODUCT_IDS` с точными ID через запятую. Если оба пусты — импорт запрещён. Неверный товар/дубликат externalId, sku, barcode или batchId отклоняет весь снимок; товары вне разрешённых ID игнорируются. Отсутствующие/неактивные позиции скрываются, старые записи сохраняются для истории заказов. Более старые `updatedAt` отклоняются. `updatedAt` записи не должен быть позже `generated_at` снимка. При ошибке остаётся последний исправный каталог, предыдущая версия архивируется.

## Бонусы

Схема: [loyalty.schema.json](../schemas/loyalty.schema.json), пример: [loyalty.json](../examples/loyalty.json). Такие же метаданные полного снимка, массив `customers`. Поля: `customerId`, `cardId`, неотрицательный `balance`, `updatedAt`, `operations`. При передаче только баланса задайте `historyAvailable: false` и `operations: []`. Сайт покажет, что история недоступна. Снимки без `historyAvailable` продолжают отображать операции по прежним правилам.

Операции: уникальный `operationId`, `receiptId`, `kind: ACCRUAL/REDEMPTION/REVERSAL`, положительный `amount`, `createdAt`, `status: SUCCESS/PENDING/FAILED/REVERSED`, необязательное описание. Баланс берётся **напрямую из 1С**, не вычисляется из операций и не меняется сайтом. `createdAt <= updatedAt <= generated_at`. Историю передавать целиком или согласованный полный исторический диапазон; UI показывает последние 50 операций. Отсутствующий клиент в полном снимке получает статус «Баланс пока не получен», не чужой баланс.

Для совместимости читаются camelCase-метаданные из исходных catalog1/bonuska, `stockUnit` и `occurredAt`; новый контракт формировать по JSON Schema с каноническими именами.

## Резервное редактирование каталога

Раздел «Управление магазином → Товары» позволяет изменить карточку, цену и остаток, скрыть позицию и добавить временный товар. Укажите фактический остаток перед вычетом резервов сайта. Временный товар показывается на витрине для покупки в магазине. Новый принятый снимок 1С применит цены, остатки и карточки из 1С и скроет временные позиции. При повторном чтении того же файла и при ошибках обмена ручные правки сохраняются.

Аккаунт связывается сотрудником через точный `customerId` после проверки клиента/карты в магазине. Телефон/email не используются для автоматической привязки. Один ID нельзя связать с двумя аккаунтами; перепривязка к другому ID запрещена. Проверки и сотрудник попадают в аудит. Общий loyalty.json никогда не выдаётся через API.

## Заказы и остатки

`C:\HOPS\data\orders\<id>.json` — локальные заказы, `outgoing\orders\<id>.json` — подготовка будущего импорта. Отправка/приём 1С автоматически **не реализованы**. Значение `AWAITING_1C_CONFIRMATION` не означает обмен. Программист 1С должен обеспечить идемпотентный импорт по `id` и `checkoutKey`, сопоставление внешних ID товаров, единиц и чеков. Повторная версия файла с тем же ID обновляет статус, не создаёт новую продажу.

При оформлении HOPS атомарно резервирует остаток, проверяет цену, владельца корзины и ключ повторного запроса. Повтор запроса создаёт тот же заказ. Новая выгрузка обновляет физический остаток, сохраняя неподтверждённые резервы. Отмена снимает резерв, выдача сама по себе его не снимает: это предотвращает повторную продажу до отражения чека в 1С.

До автоматического протокола подтверждения сотрудник после выдачи проводит продажу в 1С, проверяет чек, дожидается **новой** исправной выгрузки, учитывающей продажу, и подтверждает ID чека в админке. Только тогда локальный резерв освобождается; аудит/файл явно указывают ручное подтверждение сотрудником. Подтверждать старую выгрузку или повторно использовать чек нельзя.

Регулируемые категории и алкоголь на сайте доступны для просмотра; дистанционное оформление выключено. Для будущего включения нужна отдельно подтверждённая магазином схема и отдельное изменение политики; одного поля `onlineOrderEnabled` из 1С недостаточно. Проверка 18+ сохранена.
