# HOPS

Магазин на Next.js, TypeScript, PostgreSQL и Prisma. Сохранены светлый дизайн и оранжевые акценты исходного сайта. Заказы оформляются только на самовывоз, без доставки и онлайн-оплаты. Каталог после установки пустой; тестовые товары не создаются.

## Запуск через Docker

Нужны Docker Engine и Docker Compose v2.

1. Скопируйте `.env.example` в `.env`.
2. Задайте уникальный `POSTGRES_PASSWORD`, например результат `openssl rand -hex 32`. Для локального запуска оставьте `APP_URL=http://localhost:3000` и `COOKIE_SECURE=false`.
3. Запустите:

   ```sh
   docker compose up --build -d
   ```

Откройте [http://localhost:3000](http://localhost:3000). Compose запускает PostgreSQL, применяет миграции, создаёт настройки и точку самовывоза, затем запускает сайт и обработчик обмена. Данные хранятся в постоянном томе `postgres-data`. База не публикует порт наружу.

Администратор создаётся отдельно командой `admin:create` с переданными на время запуска `ADMIN_EMAIL` и `ADMIN_PASSWORD`; общих паролей нет. Инструкции для Bash, Windows, GitHub и VPS — в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Разработка

Требуются Node.js 22.12+ и PostgreSQL 16. Создайте `.env`, задайте `DATABASE_URL` к доступной локальной базе. Compose не открывает порт БД; для разработки можно использовать отдельный локальный PostgreSQL или приватный Compose override.

```sh
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Seed повторяемый: создаёт только исходные настройки и точку самовывоза, без клиентов, отзывов и товаров. Контакты унаследованы из исходного проекта и требуют проверки владельцем перед публикацией.

## Проверки

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E запускаются против production-сервера и отдельной тестовой PostgreSQL после миграции и seed. Тест регистрации создаёт тестового пользователя. Проверка оформления, админки и модерации использует временные технические записи только в базе `hops_test` с явно заданным `TEST_DATABASE_URL`, затем удаляет их. Эти записи не входят в seed или рабочий каталог. Доступность проверяется axe; мобильная сетка — при ширине 320, 375 и 768 px. В GitHub Actions настроены проверки с PostgreSQL и проверка запуска Docker Compose. Фактически выполненные локальные проверки — в [docs/VERIFICATION.md](docs/VERIFICATION.md).

Если Chrome уже установлен, локально можно задать `PLAYWRIGHT_CHANNEL=chrome` вместо загрузки Chromium. Для проверки уже запущенного тестового сервера задайте `PLAYWRIGHT_BASE_URL`; его `APP_URL` должен совпадать с этим адресом. Не запускайте E2E против рабочей базы.

## Страницы и данные

Главная, каталог, карточка товара, наличие и поступления, корзина, оформление самовывоза, кабинет, бонусы, заказы, отзывы, контакты, документы и админка. Состояние магазина, сессии, корзины и операции обмена сохраняются в PostgreSQL. Авторизация проверяется сервером, пароль хранится как хеш; браузер получает защищённую cookie с непрозрачным токеном.

## Интеграция с 1С

Предусмотрен адаптер товаров, цен, складских остатков, поступлений, заказов, статусов, поиска клиентов и бонусных операций, очередь, журнал, идемпотентность и повтор ошибок. `ONE_C_MODE=test` не наполняет каталог. Реальный обмен требует предоставленного API и реализации адаптера по его контракту; переключение в `live` до реализации завершается явной ошибкой. Не представляйте тестовый обмен как подключение к 1С.

Перед публичным запуском настройте HTTPS, `APP_URL`, secure cookies, резервное копирование, реальные реквизиты и документы владельца. Подробности — в инструкции развёртывания.
